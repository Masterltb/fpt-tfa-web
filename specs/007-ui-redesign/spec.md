# 007: UI Redesign — Implement UI-demo screens

## Source
`web/src/UI-demo/` — Generated by Figma Make. Contains 13 fully-coded screens.

## Design System
- **Font**: Inter (system-ui fallback)
- **Primary**: `#4F46E5` (indigo-600)
- **Background**: `#F9FAFB` (gray-50)
- **Card**: `#ffffff`
- **Border**: `rgba(17,24,39,0.08)`
- **Stack**: TailwindCSS (utility-first inline classes) + lucide-react icons

## Architecture Goal
Replace current `web/src/styles.css` + bespoke components with the UI-demo design language, **without adding Tailwind** (the existing project uses Vanilla CSS). We will port the designs into existing CSS class patterns and update each component.

## Screens to Implement

### Student Role (8 screens)
1. **StudentDashboard** — Welcome banner, profile completion, announcements, upcoming deadline
2. **StudentProfile** — Name, student ID, major, year, bio, contact info
3. **StudentSkills** — Skill catalog browser by category, proficiency slider 1–5, tag-based UI
4. **StudentAvailability** — 7-day × 3-slot grid (toggle cells), summary
5. **StudentPreferences** — Primary role picker, ranked roles, avoid roles, must-pair / cannot-pair requests
6. **StudentReview** — Read-only summary of entire profile before submission
7. **StudentTeam** — Assigned team card, teammates list with roles, rationale, shared availability

### Lecturer Role (5 screens)
8. **LecturerDashboard** — KPI cards, recent activity feed, cohort status overview
9. **LecturerCohorts** — Cohort list table with status badges, progress bars
10. **CohortWorkspace** — Tabbed workspace: Students | Requirements | Constraints | Formation | Results | Analytics
11. **FormationBoard** — Full-screen Kanban-style drag-and-drop team builder
12. **Shell (Student + Lecturer)** — Shared header, sidebar navigation, role switcher

## Implementation Strategy
Since the existing project uses **Vanilla CSS** (not Tailwind), we will:
1. Extract the design tokens from `theme.css` → add to `styles.css` as CSS custom properties (already partially done).
2. Write new CSS classes that mirror the Tailwind utilities used in UI-demo.
3. Port each screen component one-by-one, replacing Tailwind classes with our CSS classes.
4. Keep API integration wired via `AuthContext` + `api.ts` (no mock data in production).
